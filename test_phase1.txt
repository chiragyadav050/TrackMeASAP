BLOCKED — WHAT IS MISSING AND HOW TO FIX IT
===============================================================================

BLOCKED ITEM : Browser-level E2E tests (25 tests) and any real sign-in.

WHAT IS MISSING
  Real Clerk API keys. The committed .env holds syntactically valid
  placeholders that no Clerk instance stands behind.

WHY IT BLOCKS BROWSERS SPECIFICALLY
  A Clerk development key (pk_test_…) makes the middleware perform a
  "handshake": when the __clerk_db_jwt dev-browser cookie is missing, the
  browser is redirected to the instance's Frontend API host to obtain it.
  With the placeholder key that host does not exist, so Clerk answers:

    {"errors":[{"message":"Invalid host",
                "long_message":"We were unable to attribute this request to an
                 instance running on Clerk...","code":"host_invalid"}]}

  and the browser ends up on *.clerk.accounts.dev instead of the application.

  This was diagnosed directly, by capturing the browser's console and final
  URL — not inferred. Server-side requests (curl, the health endpoint,
  Playwright's `request` fixture) are unaffected, which is why the API tests
  pass and only browser tests are blocked.

HOW TO FIX IT
  1. Create an application at https://dashboard.clerk.com
  2. Open API Keys and copy both values into .env:
       NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY="pk_test_…"
       CLERK_SECRET_KEY="sk_test_…"
  3. pnpm test:e2e

  tests/e2e/clerk-env.ts detects a real instance by decoding the publishable
  key, so the 25 skipped tests begin running automatically. No code change is
  needed.

WHAT WAS NOT DONE, AND WHY
  Clerk was NOT mocked to make these tests go green. A mocked auth test
  asserts only that the mock behaves like the mock. Skipping loudly with a
  documented reason is the honest result.

ALSO NOT COVERED (requires a signed-in session, i.e. real keys plus a test
user): the authenticated app shell, the onboarding flow end-to-end, the
settings form writing to the database, and the command palette. The wiring
for this (@clerk/testing) is documented in docs/DEVELOPMENT.md but not
installed, because it cannot be verified here.
